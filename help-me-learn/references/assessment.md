# Assessment and feedback

## Prepare the set

For question types, coverage, and sequencing, read [generating question sets](assessment-generation.md). Use the guidance below to collect and review the resulting attempts.

Map each question to one or more taught outcomes. Prepare expected reasoning, acceptable alternatives, and a misconception check before collecting answers. Typically use 3–5 questions, adjusted to the learner's time and outcome coverage. If the time only permits one, explicitly leave uncovered outcomes unassessed.

Use explanation, application, and transfer appropriately. Multiple choice can reduce response effort, but a correct selection alone is weak evidence of reasoning; ask for a brief reason when needed. For design, writing, or other open-ended work, define relevant criteria rather than a single prescribed answer.

Keep the answer key separate from learner-facing questions. In file workflows, use a separate agent-notes file if needed; this is a presentation separation, not a security guarantee. Never describe local files as inaccessible to the learner.

## Collect

Default to one numbered question per turn. Acknowledge receipt without implying correctness, then show the next question. Do the full review after all submitted answers, or when the learner ends the set. If they request immediate feedback, switch modes. Do not withhold help to protect a score.

Store each attempt rather than overwriting earlier responses. Record `none`, `hint`, or `solution` assistance for that attempt. A copied revealed solution is not independent evidence. Use a fresh equivalent problem to check subsequent understanding.

## Evaluate

Compare reasoning with the outcome and criteria, not exact wording. Identify the earliest consequential error and its effect. Credit correct intermediate steps. Ask a narrow follow-up if the answer is too ambiguous to evaluate. Accept valid alternatives, including those missing from the original key; correct a flawed key or question openly.

For each answer provide:

1. What worked.
2. The actual gap, linked to the learner's words or step.
3. A correct worked solution with necessary reasoning.
4. Why their method fails here, or what conditions would make it valid.
5. A fresh retry for a meaningful gap, with the answer withheld initially.

Use the [review template](../assets/answer-review.md) if creating a review artifact. Keep feedback proportional: a correct answer needs confirmation and useful reasoning, not an invented criticism. Cite relevant page/section locators when available. Never invent the learner's reasoning.

## Evidence labels

| Outcome status | Evidence |
| --- | --- |
| `unassessed` | No interpretable attempt for this outcome. Presentation or skipping does not change this. |
| `needs-practice` | An attempt shows a substantive gap. |
| `demonstrated-with-help` | Correct reasoning/application after assistance. |
| `demonstrated-independently` | Correct reasoning/application on an appropriate fresh task without help. |

Apply labels per outcome, not by averaging chapter scores. One wrong answer does not erase unrelated evidence. Store later retrieval separately as a dated attempt with `kind: delayed-retrieval`; it provides retention evidence without rewriting history.

## Example of fair review

Question: Add 1/2 and 1/3 and explain your method.

Learner: “2/5, because I add the tops and bottoms.”

Feedback: “You identified the numerators and denominators. The gap is adding denominators: halves and thirds are different-sized pieces. Rewrite them as sixths: 1/2 = 3/6 and 1/3 = 2/6, so the sum is 5/6. Adding tops and bottoms does not preserve the quantities in this addition. Try 1/2 + 1/4 using equal-sized pieces.”

A learner who correctly uses decimals or another valid method gets credit. If that method does not show an explicitly assessed outcome, such as constructing a common denominator, ask for that step rather than marking the whole answer wrong.


## Question set structure

Use explanation, application, transfer/misconception, and optional worked-reverse questions as described in [assessment generation](assessment-generation.md). Map each to the specific outcomes it assesses. Question count alone does not establish outcome coverage or mastery.
