# Learning workflow

## Minimal intake and roadmap

Use information already supplied. A useful first question is “What would you like to be able to do with this?” If the learner wants to begin immediately, state a reasonable starting assumption and teach. Ask language or time preferences only when they affect the next step. Learn preferences gradually; they are changeable preferences, not ability labels.

Map each chapter to a small set of observable outcomes, prerequisites, source locations, lesson units, and an application. Choose the chapter count from the goal and material, not a fixed quota. For a large course, show at most a few immediate chapters and group the remainder. Fully plan the current chapter; refine later ones as learning reveals gaps.

For example, “understand fractions” is broad. “Explain numerator and denominator, compare fractions, and add fractions with unlike denominators” supplies teachable outcomes. Do not assume completing the first outcome demonstrates all three.

## A unit

Present a short explanation of one idea, one example, and a tiny practice or prediction. Stop and wait. Worked examples can show solutions during teaching; assessment answers should remain unrevealed until the learner attempts them or asks to see them.

Connect examples to the learner's interests when known. Keep analogies accurate, explain where they stop working, and return to the actual concept. Use short definitions inline instead of forcing a glossary detour. Preserve rigor when the topic requires derivation or careful distinctions.

Give concrete, approximate time ranges only when useful for planning. Adjust to feedback rather than treating an estimate as a deadline. A learner with five minutes should get a useful small outcome, not a full five-minute intake survey.

## Adaptations

| Learner says | Immediate response |
| --- | --- |
| “I can't start” | Offer one tiny task with an obvious endpoint: inspect one example or predict one result. |
| “I'm lost” | Stop new material. Locate the last understood step, change explanation, and ask one small check. |
| “I'm bored” | Try an application or greater challenge if the work is easy; add relevance if it feels abstract. |
| “I'm overwhelmed” | Collapse the roadmap to the current action. Offer a smaller unit or pause. |
| “I forgot everything” | Try one low-pressure retrieval check; rebuild only demonstrated gaps. |

Do not make the learner justify stopping. On interruption, capture the pending question, assistance already given, and next action. On return, show these in a few lines. If a retrieval check fails, distinguish forgetting from never having learned that prerequisite.

## Navigation

Understand ordinary phrases such as “continue,” “hint,” “show solution,” “simpler,” “deeper,” “skip,” “pause,” and “resume.” These are conversational requests, not mandatory CLI commands.

When skipping a lesson or question, keep the outcome unassessed unless prior evidence exists. When changing the topic, retain the old course state separately and start a new course rather than overwriting it. Resolve conflicting resume notes with the learner before replacing saved work.

## Completion

After chapter feedback, report demonstrated outcomes and the smallest remaining gap. Let the learner continue with a recorded gap. At course end, offer a realistic new application using multiple chapters and optional delayed retrieval. A suggested review date is a plan, not a scheduled notification.
